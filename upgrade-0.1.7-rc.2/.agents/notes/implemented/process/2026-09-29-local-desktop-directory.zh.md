# Agent Note：无需发布工具链构建本地 Windows Desktop 目录

Status: implemented

[English](2026-09-29-local-desktop-directory.md) | 中文

## 问题

Web 命令打开浏览器，不能提供 Electron 桌面客户端。发布打包命令即使只生成解包目录，也会编译 NSIS 安装器辅助程序，并要求先配置发布策略。本地执行文件不会发布，不需要这两项准备。

## 决策

[本地 Desktop 命令](../../../../apps/desktop/README.zh.md#local-windows-client)使用现有的包准备流程，并指定未签名的 Windows 目录目标。它打包与发布版相同的 Web、Host、插件及运行时依赖闭包。专用构建标记仅对该本地未签名产物省略安装器辅助程序编译和内嵌强制更新策略。应用使用独立的本地应用标识，不含更新 feed。产物放在仓库根目录较短的 `.desktop-local` 路径下，因为更深的发布产物路径会让内置 Python 模块导入超过 Windows 传统路径上限。程序旁的记录关联构建它的源码目录；桌面 Host 将该路径传给源码升级插件，而不使用用户配置目录作为工作目录。

签名版和普通未签名发布命令保留原有的策略、安装器、签名和预检要求。本地目录命令没有上传步骤或发布完成记录。

## 考虑过的替代方案

**保留 Web 命令的快捷方式。** 它仍打开浏览器，而不是 Desktop 外壳，也无法验证 Desktop 插件激活。

**向发布命令填入占位策略和签名设置。** 占位部署元数据会进入执行文件，并可能被误认作通过验收的发布版。

**要求本地解包目录也安装 Visual Studio。** 原生辅助程序属于安装器，目录产物不会使用它。

## 影响

开发者无需发布凭据或安装器编译器即可运行真正的 Electron 执行文件。目录必须保持完整，它既不是安装器，也不是官方分发产物。移动源码目录后，必须重新构建本地客户端才能更新记录的源码升级目标。本地验证覆盖打包运行时冒烟和直接启动应用；签名安装与更新器行为仍由发布验收负责。
