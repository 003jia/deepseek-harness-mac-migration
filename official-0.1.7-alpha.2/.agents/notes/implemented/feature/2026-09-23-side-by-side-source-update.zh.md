# Agent Note: 并列目录中的源码更新

Status: implemented

[English](2026-09-23-side-by-side-source-update.md) | 中文

## Problem

定制过的源码压缩包没有可用于识别本地提交并重放到新版官方发布的 Git 历史。原地替换文件可能丢失本地工作，也可能让运行中的 Web 进程读取混合版本。

## Decision

Web 更新页通过官方 GitHub Releases API 发现版本。在干净的具名 Git 分支上，Host 获取选定的官方发布标签、创建相邻的 Git worktree，并把当前分支的提交重放到该目录。Remote 返回新目录的绝对路径及冲突状态。当前目录和进程保持原状。用户在新目录处理冲突、安装依赖、构建并启动。

服务以根包名称和 Git 目录验证源码仓库。目标提交来自官方发布标签；界面不能传入任意仓库地址。存在未提交修改或分支游离时，在创建新目录前报错。

## Alternatives considered

**覆盖当前源码目录。** 合并或构建失败会修改运行中进程所依赖的源码，因此没有采用。

**下载发布压缩包。** 压缩包无法重放已提交的定制，也无法呈现合并冲突，因此没有采用。

**安装桌面应用包。** 桌面更新器负责已打包应用的更新，不能保留源码定制。

## Consequences

准备好的目录可以审查，也可以舍弃。Git 冲突只留在新目录。源码压缩包必须先成为带定制提交的 Git 分支。按钮不会把新目录描述为已完成依赖安装、构建或运行检查。

## Testing

源码准备测试使用本地 Git 仓库覆盖成功重放和冲突。Web 设置场景以固定发布响应验证组装后的更新页和生成的 Remote。
