# Agent Note：皮肤中心——自定义背景与玻璃设置

状态：已实现

[English](2026-08-19-skin-center-background-and-glass.md) | 中文

## 问题

两项外观能力需要归宿。其一，ui-layout 里落了一个玻璃拟态调参半成品（`GlassControls` 悬浮面板）：两个滑块把 `--dsw-glass-opacity`/`--dsw-glass-blur` 写到文档根上，默认值在 React state 与 CSS `:root` 回退里重复写死、完全不持久化（每次刷新回到 85 %/12 px）、中文文案绕过 locale 服务、还常驻一个悬浮控件。其二，用户想要自定义动图背景（自己的 GIF）——一方界面没有这个能力，但 scratch 目录里的社区项目 `dsh-skins` 证明了形态：harness home 下的壁纸存储、host 供图路由、半透明面板后面的 body 固定层。

产品决策（用户确认）：图片来源只做本地上传（不做路径/URL 输入）；悬浮面板移除、功能并入新的设置页；玻璃效果扩展到全部三栏（半成品只覆盖侧栏和详情栏）。

## 决策

新建插件 `@deepseek-ai/dsh-client-ui-skin-center` 独占整个特性；ui-layout 只消费它已经认识的 CSS 变量。

**持久化。** 单一持久设置命名空间 `ui-skin-center`（七个标量字段）沿用 ui-theme 模式：Host 半注册 schema；浏览器半绑定 `ctx.settingsScope` 并采纳推送失效。默认值与 ui-layout 的 CSS `:root` 回退一致，插件加载前后的渲染一致，默认值下的运行时覆写是空操作。滑块拖动经 `input` 实时预览，指针/键盘释放时才持久化一次——写序串行化由设置作用域既有机制承担。

**跨插件协作停留在 DOM 层。** 控制器把 `--dsw-glass-*` 写到文档根、把背景层画到 body 上；ui-layout 的框架样式读取它们。布局同时接受 `--dsh-pane-opacity` 与 `--dsh-sidebar-opacity`，并在 body 带 `data-dsh-skin-bg` 或兼容标记 `data-dsh-wallpaper` 时让框架、会话、详情和侧边栏根节点交出背景。没有跨插件值导入（客户端 bundle 纯度门），也没有新的服务缝——CSS 自定义属性和 body 标记就是契约，两侧都有文档。

**上传走既有受信通道，不开新路由。** 专用逻辑 RPC 通道 `/skin-center`（`connection.rpc.handle`，`trusted-host` 级别）承载 base64 上传与删除。选它而不是自建 HTTP 路由，是因为 Connection 的 Host 侧围栏（Origin/Host、DNS 重绑定、跨站标记）在那里已经存在，且回环桥本就容忍 MiB 级请求体。供图路由 `/skin-center-image` 存在的唯一原因是 CSS `url()` 和 `<img>` 不能走 RPC 信封；它只用存储文件的字节应答 GET，别无其他。

**ref 由服务端铸造，是能力令牌。** 存储文件命名为 `<22 位 base64url id><扩展名>`；名字绝不来自用户输入，因此 ref 无法编码路径。读取把解析路径再次围栏在存储目录内（纵深防御——ref 模式本就排除分隔符）并复检 20 MiB 上限。供图路由自身不设 origin 围栏：ref 不可猜，暴露的只有上传者放入的那张图。

**背景让位，应用清底。** 插件注入的样式表画 `body[data-dsh-skin-bg]::before`（蒙版 + 模糊 + 尺寸）并清掉 body 自身背景；同一 `data-dsh-skin-bg` 属性下 ui-layout 的 `.frame` 放弃网格渐变，两层背景永不叠加。蒙版在浅色模式用白色、深色模式用深海军蓝，键于既有 `data-ds-dark-theme` 属性。

## 备选方案与取舍

- **背景的路径/URL 输入。** 社区皮肤中心有文本框；我们砍掉了。上传覆盖已确认的需求，而路径字段会重新打开宿主文件系统问题（哪些目录、何种信任）——能力 ref 设计整体回避了它们。
- **流式上传。** JSON 内 base64 把实际可用图片限制在回环上约 20 MiB。对 GIF 背景足够；更大的图片是文档化的后续工作。
- **远程浏览器同步。** 设置 RPC 仅回环可用，远程浏览器的皮肤保持进程内——继承自持久化模式，不是这里重新引入的。
- **逐栏玻璃调节。** 一对透明度/模糊值覆盖三栏；半成品面板遗留的"作用范围"问题按"全部"裁定，没有做成设置项。

## 后果

包内套件钉住 schema 默认与收敛、存储（扩展名/大小/ref 围栏、目录与超限拒绝、读失败落空）、RPC 折叠（上传/删除正路、畸形载荷、非 Error 拒绝、经 `DSH_HOME` 的默认存储委托）、供图路由（仅 GET、404/405）、控制器（作用域采纳、DOM 应用、preview 对 set、上传/删除流、样式表幂等）、设置页组件（经 `t` 的文案、滑块预览/提交、选择器复位、失败提示）、apply 接线（locale、节注册、启动投影、拆除）。逐文件 100 % 覆盖率门通过，两条目录围栏结构性不可达分支带理由 `v8 ignore` 标注。
