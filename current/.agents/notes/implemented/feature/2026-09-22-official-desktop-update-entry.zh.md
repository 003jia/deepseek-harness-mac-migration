# Agent Note：官方桌面端更新入口

Status: implemented

[English](2026-09-22-official-desktop-update-entry.md) | 中文

## 问题

桌面端侧边栏暴露的是远程访问插件带来的更新器，它检查的是个人包仓库。Settings 页面只有简单的版本对比，没有标明发布来源、解释安装包是否存在，也没有给用户可信的官方去处。

## 决策

`dsh-host-update-check` 只读取 `deepseek-ai/deepseek-harness` 的 GitHub Releases。它会在返回规范的官方发布页、发布时间以及至多一个与当前平台和架构匹配的安装包资产之前校验这些发布和下载 URL。Settings 更新页会在打开时和用户主动重试时检查；不确定进度条表示这次网络请求。页面只链接到这些官方 URL。Electron 壳提供窄范围的 preload 接口，且较新版本有匹配安装包时，点击一次「更新 DeepSeek Harness」就会下载该资产，并在完成后通过操作系统打开。传输过程会报告实际接收字节、在 GitHub 提供 SHA-256 摘要时进行校验，并保留已有文件。取消或失败不会打开安装包。安装由操作系统负责；任何路径都不会替换正在运行的源码目录。

更新包通过与呈现无关的 `settingsNavigator` 服务，将一个打开 Settings 自身 `update` 已注册分区的侧边栏操作加入界面。一个窄范围的页脚选择器移除远程访问插件相邻的个人更新器，同时保留它的远程访问按钮。

`updateCheck/check` Client Remote schema 会传递发布 URL、发布时间和安装包资产字段。Host 结果类型变更后必须重建 `@deepseek-ai/dsh-api-remotes`：旧的生成 schema 会从响应中移除这些字段，导致更新卡片在 slot 边界内崩溃，而不是正常渲染。

## 曾考虑的替代方案

**保留远程访问插件的更新器。** 否决：它的发布状态属于个人包仓库，不属于官方 DeepSeek Harness 项目。

**版本检查后自动安装。** 否决：官方发布可能没有当前平台的安装包，且源码／本地构建没有明确安装生命周期就不能安全替换自身。用户明确点击更新后才会启动已校验的安装包，安装提示仍由操作系统负责。

**让侧边栏操作打开第二个弹窗。** 否决：Settings 已经拥有更新分区以及它的焦点、关闭和无障碍行为。

## 后果

侧边栏保留远程访问，但不再展示个人仓库更新器。官方发布没有匹配的桌面安装包时，UI 会明确说明这一点，并提供官方发布页，而不是误导性的更新操作。有安装包时，点击一次就会由桌面壳将它下载到用户的「下载」目录并打开；安装仍需按照操作系统提示完成。一次性导航请求会在外壳应用后确认，避免陈旧请求再次打开 Settings。

## 测试

聚焦的单元和客户端测试覆盖官方 URL 过滤、平台及架构选择、摘要处理、流式字节进度、摘要不符时的清理、等待中的版本检查、单击打开安装包、重试、侧边栏打开和 Settings 分区导航。已组装的 Web 应用 Playwright 测试通过真实 Remote 路径记录检查中状态和无安装包结果。没有合适的发布资产时，实际安装包传输仍无法完成端到端验证。
